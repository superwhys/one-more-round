# 「又一局」前端 Agent 开发规范

本规范适用于 `web/` 目录，并继承仓库根目录 [AGENTS.md](../AGENTS.md) 中的产品规则、业务不变量、安全边界、构建流程和完成标准。发生冲突时，以用户当前明确要求和根目录规则为准。

## 1. 前端代码格式

- `src/` 下的 `.vue`、`.ts` 和 `.css` 源码必须使用项目已锁定的 Prettier 版本和 `web/.prettierrc.json`，格式化结果是排版标准；不要凭个人偏好绕过或对抗格式化工具。
- 禁止把 Vue 模板、脚本、样式或 TypeScript 逻辑压成一行。属性、表达式、对象、参数或 CSS 声明超过格式化宽度时，让 Prettier 自动换行，不手工维持难以阅读的超长行。
- 修改或新增 `.vue`、`.ts`、`.css` 文件后，在 `web/` 目录运行 `pnpm format`，交付前运行 `pnpm format:check`。根目录 `make check` 也必须包含格式检查。
- 格式化只能改变排版，不能借机重写逻辑、调整文案或清理无关代码。运行后检查 diff，确认没有超出当前任务的变更。

## 2. 组件与代码组织

- 使用 Vue 3 Composition API、`<script setup lang="ts">`，启用严格类型检查；避免 `any`，API 请求集中封装，页面不得重复拼装认证或错误处理。
- 按页面和业务职责组织组件，只有出现真实复用时再提取；不为首版引入无必要的状态管理、组件库或复杂抽象。
- 每个渲染路由使用独立的 `views/**/*.vue` 页面；页面间的复用下沉到组件，不通过判断路径把多个页面塞进同一个文件。
- 新增组件前先查找现有实现，优先复用；保持当前目录、命名、Props、Emits 和类型导入风格。

## 3. 产品交互

- 手机导航为「回顾」「桌游」「小组」，「记一局」始终容易找到；电脑沿用相同信息结构。
- 暖白背景、深色文字、少量橙色强调；首页以回忆时间线为主，结果同时用文字和图标表达，不只靠颜色。
- 表单默认当前小组和今天，优先显示最近游戏与玩家，玩家名单需用户确认。可选字段渐进展开，避免增加主流程输入。
- “再记一局”沿用游戏和玩家，清空结果、分数与回忆；不得复用上一局提交的幂等键或照片。
- 草稿按账号和小组隔离，在当前设备自动保存；保存失败保留输入，成功后清除，退出账号清除本地草稿。切换账号或小组不串用草稿。
- 删除需二次确认；加载、空数据、失败、重试、上传进度和并发冲突有可理解的中文反馈。
- 表单有可访问标签，支持键盘操作和清晰焦点；手机全流程无横向溢出，触摸目标易点击。

## 4. 验证

- 前端改动至少执行 `pnpm format:check`、`pnpm typecheck` 和相关测试；生产构建按改动范围执行。
- 涉及页面行为或样式时，用浏览器验证实际目标路由，并覆盖受影响的桌面和窄屏布局；不能用编译通过代替交互验证。
- 交付时说明实际运行的命令和未验证项，不把格式检查、类型检查或构建中的任一项表述成完整功能验收。
