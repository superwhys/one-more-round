# 「又一局」产品需求文档 PRD
**版本：V0.1 · 熟人邀请试用版**

## 一、产品定位与目标

- **GitHub 项目名：** `one-more-round`
- **Web 名称：** 又一局
- **标语：** 记下每一局的输赢与相聚。
- **产品定位：** 面向熟人桌游小组的共同对局日记。

用户在聚会结束后，用手机快速记录游戏、玩家和结果，可附感想与照片；之后，小组成员可以回顾共同经历，查看轻量统计。

**首版核心目标：让“记一局”足够简单，让记录值得再次打开。**

已确定的产品方向：

| 维度 | 首版选择 |
|---|---|
| 使用人群 | 经常一起玩桌游的熟人小圈子 |
| 记录时机 | 对局结束后快速录入 |
| 游戏规则 | 通用记录，不开发单款桌游计分规则 |
| 组织方式 | 固定小组，记录在组内共享 |
| 玩家身份 | 记录人需要账号，其他玩家可以只有昵称 |
| 内容重心 | 对局回忆、文字与照片，辅以轻量统计 |
| 设备 | 手机浏览器优先，兼顾电脑 |
| 游戏资料 | 接入外部桌游资料库，允许手动补充 |
| 发布范围 | 先邀请自己和朋友免费试用 |

首轮验证目标：邀请 2—3 个真实小组试用两周。对于已有游戏、已有玩家、不附照片的普通对局，目标是 **60 秒内完成记录**；同时观察小组是否在下一次聚会继续使用、是否有其他成员主动查看记录。这些是验证目标，不是已有结果。

## 二、核心流程与页面

### 2.1 首次使用

`接受试用邀请 → 登录 → 创建小组`，或 `打开小组邀请 → 验证邮箱并注册/登录、加入小组 → 建立自己的玩家档案 → 记录第一局`。

- 创建小组填写小组名称和自己的玩家昵称。
- 创建者成为组主，并自动创建、关联自己在该小组中的玩家档案。
- 录入整桌玩家时，可直接输入昵称，不要求玩家注册。
- 朋友后续登录加入小组，可以创建新的玩家档案，或申请关联已有玩家档案以保留之前的战绩；两种方式均由组主确认关联。

### 2.2 日常记局

`点“记一局” → 选游戏 → 选玩家 → 填结果 → 可选补充回忆 → 保存`

减少输入的默认行为：

- 默认当前小组、今天的日期。
- 游戏优先展示最近玩过的。
- 玩家优先展示最近参与的，用户确认本局名单。
- 感想、照片、时长、地点均不必填写。
- 保存后展示“查看记录”和“再记一局”。

“再记一局”沿用游戏和玩家，清空结果、分数与回忆内容，适合连续玩同一个游戏。

### 2.3 页面结构

手机底部导航采用 **「回顾」「桌游」「小组」**，提供始终容易找到的「记一局」主按钮。电脑端沿用相同信息结构，增加列表与详情的展示空间。

| 页面 | 核心内容与操作 |
|---|---|
| 回顾首页 | 当前小组、轻量统计摘要、按日期倒序排列的对局时间线 |
| 记一局 | 游戏、玩家、结果；展开后填写时间、地点、感想与照片 |
| 对局详情 | 游戏与日期、参与者、结果、分数、照片、感想、记录人 |
| 桌游列表 | 本组玩过的游戏、次数、最近游玩日期 |
| 桌游详情 | 基础资料、本组中文别名、该游戏的历史对局和统计 |
| 玩家详情 | 参与次数、常玩游戏、最近对局、分游戏战绩 |
| 小组页 | 成员、昵称玩家、邀请入口、组内统计和管理设置 |

时间线卡片优先展示 **游戏名称、玩家、结果和回忆**，有照片时展示首张缩略图。首页不使用排行榜作为主视觉。

视觉采用暖白背景、深色文字和少量橙色强调，营造轻松的桌边记录感；结果同时使用文字和图标表达，不能仅靠颜色区分。

## 三、首版功能与业务规则

### 3.1 小组、账号与玩家

**账号和玩家档案分开管理：**账号用于登录与权限，玩家档案用于记录“谁参加过对局”。

| 角色 | 权限 |
|---|---|
| 组主 | 查看全部记录、记录对局、修改或删除组内记录、管理成员、确认玩家关联 |
| 普通成员 | 查看全部组内记录、记录对局、修改或删除自己创建的记录、添加游戏与昵称玩家 |
| 未注册的昵称玩家 | 作为参与者出现在记录中，没有访问权限 |
| 非小组成员 | 不能查看组内对局、照片与统计 |

具体规则：

- 一个账号可以加入多个小组；每条对局只属于一个小组。
- 玩家档案按小组隔离，同名玩家不自动合并。
- 添加重名玩家时，提示选择已有玩家，或使用可区分的昵称。
- 成员加入其他小组后，可创建新玩家档案并申请关联，或申请关联已有玩家档案；两种方式均由组主确认，不能仅凭昵称自动认领。
- 每个账号在同一小组最多关联一个玩家档案，档案也只能关联一个账号。
- 小组邀请链接由组主生成和撤销，7 天有效，可供多位朋友使用。新用户验证邮箱后自动注册并加入该组，无需另一个试用邀请码；已有账号验证邮箱后直接加入，已登录成员可进入小组。持有或被转发有效链接的人均可加入，生成时明确提示分享范围。
- 加入前仅凭有效邀请显示小组名称，不展示成员、对局、照片或统计。注册、加入小组与创建会话在同一事务提交；提交时重新校验邀请，撤销或过期时不留下半完成的注册。
- 浏览器当前标签页暂存待处理邀请和验证码发送进度，刷新后可继续；成功、取消邀请或退出登录时清除相应状态，不保存验证码或会话凭据。
- 成员退出或被移除后失去访问权限，历史对局中的参与记录保留。
- 组主退出前需要转让组主身份。

**默认登录方案：邮箱验证码。**首次注册需要有效的试用邀请或小组邀请。管理员的试用邀请用于首批用户注册并自行创建小组，使用一次即失效；小组邀请用于注册并加入指定小组。首版不提供无邀请的公开注册入口，也不要求绑定 BGG 账号。

### 3.2 游戏检索与资料

首版外部资料源采用 **BoardGameGeek（BGG）**。使用其名称搜索与详情接口导入基础资料，不同步 BGG 用户、收藏或对局记录。[BGG API 文档](https://boardgamegeek.com/wiki/page/BGG_XML_API2)

搜索流程：

1. 先搜索本组已有游戏及中文别名。
2. 用户主动选择“搜索更多桌游”后查询 BGG。
3. 搜索结果展示名称、年份，选中后获取详情与可用封面。
4. 导入后保留稳定的 BGG ID，可填写本组习惯使用的中文名称。
5. 搜不到或服务不可用时，可以仅输入名称创建游戏。

规则：

- 同一小组重复导入同一个 BGG ID 时复用已有游戏。
- 自定义游戏可以后续关联 BGG 条目；若该条目已存在，由组主确认合并，历史记录一并保留。
- 本组中文别名不改动外部原始名称。
- 不承诺外部库覆盖所有中文名称；支持用原文名称重试。
- 封面缺失时使用统一占位图，不影响录入。
- 首版以基础游戏为记录对象，扩展包可写入备注，不做扩展包关系管理。

**接入前置条件：**BGG 当前要求注册应用并获得授权；服务端调用并缓存结果，令牌不下发浏览器。公开展示数据时按要求提供来源标识。授权尚未获批时，内测可先使用手动添加，但不能把外部检索标为已完成。[BGG 官方接入说明](https://boardgamegeek.com/using_the_xml_api)

### 3.3 对局记录

| 字段 | 必填 | 规则 |
|---|---|---|
| 游戏 | 是 | 选择已有、外部导入或手动添加 |
| 日期 | 是 | 默认今天，支持补录历史日期 |
| 玩家 | 是 | 至少一人；同一玩家不能重复出现 |
| 对局模式 | 是 | 个人竞技、组队竞技、合作 |
| 结果 | 是 | 可明确选择“未记结果”，不强迫补全 |
| 分数 | 否 | 支持负数与小数；空白不等于零 |
| 时长 | 否 | 手动填写分钟，不提供实时计时 |
| 地点 | 否 | 自由填写，可复用近期地点 |
| 一句话回忆 | 否 | 最多 500 字 |
| 照片 | 否 | 最多 6 张，单张不超过 10 MB |

**结果按三种模式处理：**

| 模式 | 录入方式 | 统计处理 |
|---|---|---|
| 个人竞技 | 选择获胜玩家，支持共同获胜；或选择全局平局、未记结果 | 记录玩家胜局与有效竞技局数 |
| 组队竞技 | 将玩家分为至少两队，填写队伍结果与可选队伍分数 | 队员继承本队结果，单独统计组队战绩 |
| 合作 | 全队胜利、全队失败、未记结果；可填团队分数 | 单独计算合作成功率 |

补充规则：

- 个人竞技至少两人；单人游戏使用合作模式记录挑战成功或失败。
- 每名组队玩家只能属于一支队伍，各队至少一人。
- 不根据分数自动判断赢家，避免高分胜、低分胜和特殊规则冲突。
- 共同获胜与平局分开：共同获胜的玩家各记一胜；平局无人记胜。
- 未记结果的对局保留在时间线并计入游玩次数，不计入胜率。
- 不提供逐轮计分、自动规则结算和复杂名次录入。

**保存体验：**

- 表单在当前设备自动保留草稿，保存成功后清除；退出账号时清除本地草稿。
- 保存失败保留输入，允许重试；重复点击不能生成重复对局。
- 照片独立上传、展示进度；失败可重试或移除，不阻止用户保存其余内容。
- 支持 JPEG、PNG、WebP，上传时压缩并去除定位元数据；其他格式提示转换。
- 编辑后显示最近修改人和时间；删除需二次确认，并同步更新统计。
- 两人同时修改同一条记录时提示刷新，避免静默覆盖。

### 3.4 回顾与统计

首版统计回答四个问题：

- 我们最近玩了多少局？
- 最常玩哪些游戏？
- 哪些朋友经常参加？
- 某个人玩某款游戏的表现如何？

统计口径：

| 指标 | 定义 |
|---|---|
| 游玩次数 | 当前筛选范围内的对局记录数，包含未记结果 |
| 玩过游戏数 | 对局关联的去重游戏数 |
| 玩家参与次数 | 玩家参与的对局数 |
| 竞技胜率 | 胜局数 ÷ 已记录结果的竞技局数；平局进入分母 |
| 合作成功率 | 成功局数 ÷ 已记录结果的合作局数 |
| 常玩游戏 | 按对局次数排序 |

- 胜率按具体游戏与模式分别展示，不生成跨游戏综合实力排名。
- 所有比例同时展示样本数，例如“60% · 3 胜 / 5 局”。
- 没有有效样本显示“暂无数据”，不显示为 0%。
- 支持按日期区间、游戏、玩家筛选；默认展示全部记录。
- 小组总对局数按记录计数，不能把每个玩家的参与次数相加。
- 照片及原图与对局使用相同访问权限，不能通过公开直链绕过小组权限。

## 四、数据边界与版本范围

### 4.1 最小数据模型与接口能力

| 核心对象 | 作用 |
|---|---|
| 账号、组成员关系 | 登录身份、所属小组及权限 |
| 小组、邀请 | 共享边界与加入机制 |
| 玩家档案 | 昵称、可选关联账号、历史参与关系 |
| 游戏条目 | 本地资料、中文别名、可选外部来源 ID |
| 对局、参与结果 | 游戏、日期、模式、玩家或队伍、结果与分数 |
| 对局照片 | 图片、顺序、所属对局与访问权限 |

前后端需要提供：登录、小组与邀请管理、玩家关联、游戏搜索与导入、对局增删改查、图片上传与授权访问、筛选和统计能力。

所有组内读写由服务端检查成员身份；统计直接基于对局与参与结果计算，避免维护另一份容易失真的手填战绩。

对局和用户内容存储在自己的服务中。已保存的记录与已导入游戏不依赖 BGG 实时可用。

### 4.2 首版边界

**V0.1 必须交付：**

- 邀请登录、创建和加入小组。
- 昵称玩家、账号关联。
- BGG 搜索导入、中文别名、手动添加。
- 三种模式的通用对局记录。
- 感想、照片、编辑和删除。
- 时间线、游戏与玩家详情、轻量统计。
- 手机与电脑响应式适配。

**后续再考虑：**

- 聚会相册、月度回顾、年度总结。
- 对局分享卡片、数据导出。
- 收藏与想玩清单。
- 个别热门桌游的专属计分模板。

**首版不做：**实时多人计分、公开社区、评论聊天、陌生人组局、Elo 排名、桌游店运营、付费订阅、原生 App，以及完整离线同步。

## 五、验收与试用安排

### 5.1 核心验收场景

| 场景 | 通过标准 |
|---|---|
| 一人记录整桌 | 只有记录人注册，也能添加其他玩家并保存对局 |
| 快速记局 | 已有游戏和玩家、不附照片时，目标用户能在 60 秒内完成 |
| 朋友加入 | 加入小组后可查看历史记录，关联档案后历史统计不重复 |
| 特殊结果 | 共同获胜、平局、负分、空分数、未记结果均正确保存与统计 |
| 团队与合作 | 组队结果正确映射到成员，合作结果不混入竞技胜率 |
| 外部服务异常 | 搜索超时或授权失效有明确提示，仍能选择本地游戏或手动添加 |
| 图片异常 | 上传失败可重试或移除，其余记录可以保存 |
| 弱网与重试 | 不丢已填写内容，不产生重复记录 |
| 编辑与删除 | 时间线、详情和统计同步更新；并发编辑不静默覆盖 |
| 权限隔离 | 非成员及已移除成员无法读取记录或照片，也无法伪造写入 |
| 设备适配 | 手机完成全流程无横向溢出，电脑能方便地筛选与查看详情 |

### 5.2 交付顺序

1. **跑通核心闭环：**账号、小组、玩家、手动游戏、记录、回顾。
2. **补齐完整首版：**BGG 接入、照片、玩家关联和统计；BGG 授权申请提前进行。
3. **熟人试用：**邀请 2—3 个小组，覆盖至少两次真实聚会，收集实际录入时间和卡点。

技术监测只保留必要项目：记局保存失败率、图片上传失败率、外部搜索失败率与延迟。产品观察记录开始、保存成功、耗时和回访，不将感想正文或照片内容写入分析事件。

试用后优先修复影响“愿意记、记得快、找得到”的问题，再决定是否扩展功能。

**本版默认假设：**中文界面、邮箱验证码登录、邀请制免费试用、默认北京时间、组内记录私有；不预设前后端框架和部署厂商，技术选型在开发方案中确定。
