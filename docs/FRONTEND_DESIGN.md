# 又一局 · 前端产品稿 V0.1

状态：待评审。依据 [PRD](PRD.md)，本稿描述页面、内容层级与交互提案，不代表业务功能已经实现。示例人物、对局和统计均为设计演示数据。

本文仅保留前端设计决策，不提供单独的可点击产品稿入口。正式业务页面以 PRD、接口契约和实际实现为准。

## 1. 体验方向

打开产品，先看到和朋友一起玩过的日子；记局时，只把必须确认的内容放在眼前。

- 手机是主要使用场景；电脑适合筛选和回顾，信息结构保持一致。
- 暖白底、墨色文字、陶土橙主按钮；照片和回忆比数字更醒目。
- 页面以“日记”组织，不采用排行榜、竞技等级或运营后台式大面积指标卡。
- 普通记录采用一张连续表单，游戏和玩家选择通过选择面板完成，避免反复跳页。
- 重要反馈立即出现；导航不加等待动画，弹层只使用短暂淡入，尊重减少动态效果设置。

## 2. 导航与页面关系

```text
试用邀请 → 邮箱登录 → 创建/加入小组 → 回顾
                                      ├─ 对局详情 → 编辑对局
                                      ├─ 记一局 → 保存成功
                                      │             ├─ 查看记录
                                      │             └─ 再记一局
                                      ├─ 桌游 → 桌游详情 → 历史对局
                                      └─ 小组 → 玩家详情 / 邀请 / 管理
```

手机底部固定「回顾 / 桌游 / 小组」。非编辑页面保留「＋ 记一局」入口；进入记局或编辑页面后，以底部保存操作替代全局导航，给表单留出空间。返回时保留草稿。

电脑采用左侧导航，主体内容居中；回顾页可在右侧补充常玩游戏，小屏不额外增加信息层级。

当前小组位于页面顶部，可点击切换。切换时清晰显示新小组名称，并重置不适用的筛选；不同小组的草稿分开保存。

## 3. 回顾首页

**用户要回答：最近一起玩了什么？哪一局值得再看？**

从上到下：

1. 当前小组，例如「周五不散场」，旁边是小组切换入口。
2. 标题「一起玩过的日子」，轻量摘要「12 局 · 5 款桌游」。数字属于当前筛选范围，演示稿需使用可核对的示例数据。
3. 筛选入口：日期、桌游、玩家。默认全部，选中条件显示为可移除标签，提供清空筛选。
4. 按日期倒序的时间线，以日期分组，不把每名玩家拆成一条对局。
5. 到底后加载更多；无记录与筛选无结果使用不同空状态。

卡片示例：

```text
9 月 12 日 · 周六
┌──────────────────────────────┐
│ [桌游封面] 璀璨宝石            │
│            个人竞技 · 4 人     │
│ 小林 / 阿远 / 可可 / 我        │
│ ♔ 可可获胜                    │
│ “最后一张牌翻盘，大家都不服。” │
│ [本局首张照片，可选]           │
│ 晚上八点的小桌 · 35 分钟       │
└──────────────────────────────┘
```

整张卡片进入详情。结果必须有文字，分别展示“共同获胜”“全局平局”“全队胜利”“全队失败”“未记结果”；无照片时自然收缩，不留空白占位区。可选时长没填就不显示。

空状态文案：「第一次相聚，从这一局开始。」主操作「记第一局」。筛选为空时显示「这个范围还没有对局」，主操作「清空筛选」。

## 4. 记一局

**用户要完成：游戏、玩家、结果，确认后保存。**

顶部展示返回、标题「记一局」、当前小组；日期默认今天但始终可见，点击可补录历史日期。

| 区域 | 默认展示 | 点击后的行为 |
| --- | --- | --- |
| 玩了什么 | 最近桌游；未选时“选择桌游” | 搜本组名称/中文别名，选择或手动添加 |
| 和谁一起 | 最近参与玩家，明确勾选状态 | 多选现有玩家；输入昵称添加临时参与者档案 |
| 怎么记结果 | 个人竞技 / 组队竞技 / 合作 | 改变结果区域；不默默沿用不兼容结果 |
| 本局结果 | 对应模式的结果选项 | 必须主动选结果，也可选“未记结果” |
| 留点回忆 | “添加回忆、照片和更多信息” | 展开感想、照片、时长 |
| 底部操作 | 保存这局 | 校验、提交、成功反馈 |

### 个人竞技

结果选项「选获胜玩家 / 全局平局 / 未记结果」。选择获胜玩家后直接点选名单，可选多人；多人被选中时标为“共同获胜”。分数放在各玩家行内的可选输入中，不根据分数勾选赢家。

### 组队竞技

先显示 A 队、B 队，每名玩家通过点选归入一队；支持添加队伍，避免强制拖拽。所有人分队完成后填写队伍结果与可选队伍分数。

待确认：组队是否允许多队共同获胜、全局平局。PRD 未明确定义这两个枚举，视觉稿可展示“两队、一队获胜”的典型状态，但正式实现前需明确完整口径。

### 合作

结果使用「全队胜利 / 全队失败 / 未记结果」三个大按钮，可选填团队分数。单人挑战同样使用此模式。切换为个人竞技且只有一名玩家时，提示至少选择两人。

### 可选回忆与照片

- 一句话回忆：多行输入，提示“这局有什么值得记住？”，显示 500 字上限。
- 照片：缩略图网格与添加按钮，显示已选数量 / 6；上传进度、失败重试和移除都在图片位置反馈。
- 上传失败时允许保存其余内容，明确说明未成功图片不会进入该条记录。
- 时长使用分钟。

保存按钮提交中显示“正在保存…”，防止连续点击。失败保留表单，错误显示在相关字段或保存区；成功页显示“这一局，记下了”，提供「查看记录」「再记一局」。

“再记一局”只沿用游戏与玩家，结果、分数、感想和照片清空。

## 5. 对局详情与编辑

内容顺序：游戏与日期 → 模式和结果 → 玩家/队伍与分数 → 感想与照片 → 时长 → 记录人、最近修改人及时间。

- 玩家名可进入玩家详情；游戏名可进入桌游详情。
- 图片点击后查看大图，可返回原位置，不公开生成分享链接。
- 有权限的用户在更多菜单中看到「编辑」「删除」，普通成员看不到他人记录的修改入口。
- 编辑复用记局表单，保存后回到详情。版本冲突显示“这条记录刚刚被修改，请刷新后再试”，保留用户输入供核对，不自动覆盖。
- 删除二次确认说明“删除后会同步更新组内统计”，确认按钮明确写「删除这局」。

## 6. 桌游与玩家详情

### 桌游列表

搜索框下展示本组玩过的游戏，卡片包括封面、中文别名/名称、游玩次数和最近日期。手机两列、窄屏保证名称可读；电脑可增加列数。手动添加和搜索更多桌游是明确的独立入口。

外部搜索只有用户主动触发后进行。失败显示「暂时无法搜索更多桌游」，保留「重试」「手动添加」；已有游戏仍可选择。无封面使用统一占位，不伪造官方封面。

### 桌游详情

顶部是游戏基础资料与本组中文别名，外部资料附来源标识；下方展示本组游玩次数、分模式统计和该游戏时间线。「再玩一局」进入已选游戏的记局表单。

### 玩家详情

顶部显示昵称和是否已关联账号，正文是参与次数、常玩游戏、最近对局以及分游戏/模式战绩。

战绩展示示例：「璀璨宝石 · 个人竞技：60% · 3 胜 / 5 局」。合作成功率独立展示，没有有效样本时为「暂无数据」。不设置跨游戏总胜率或综合实力榜。

## 7. 小组与邀请登录

小组页依次展示小组名称、组内摘要、玩家档案、账号成员和管理入口。玩家档案与账号成员分区，避免让“没有账号”看起来像异常状态。

- 玩家行：昵称、已关联/未关联状态，进入玩家详情；成员可添加昵称玩家。
- 成员行：名称、组主/成员身份。移除等管理操作仅组主可见。
- 关联玩家：本人选择已有未关联档案后提交申请，状态显示「等待组主确认」；不因昵称相同自动关联。
- 邀请：组主可生成、复制和撤销小组邀请；界面说明“7 天内可多人使用，验证邮箱即可注册并加入”，并提示被转发链接的人也能加入和查看历史对局。
- 退出：普通成员可退出；组主先转让身份。提示历史参与记录会保留。

试用邀请用于首批用户注册并自行创建小组；小组邀请允许注册并加入指定小组。打开小组链接后，登录页显示目标小组，隐藏试用邀请码输入框；验证邮箱后点击「登录并加入小组」。已登录账号确认加入，已有成员显示「进入小组」。加入前仅展示小组名称，失效/撤销邀请显示原因及返回入口，不展示私有对局。

登录页采用邮箱 + 验证码，发送后显示 60 秒重发倒计时、可更换邮箱；不做公开注册按钮。验证码 10 分钟有效；当前标签页保存待处理邀请、邮箱及发送时间以支持刷新恢复，不保存验证码，成功/取消/退出后清除相应状态。

## 8. 状态与适配清单

| 状态 | 展示与反馈 |
| --- | --- |
| 首次加载 | 保持页面结构的骨架占位，不伪造统计数字 |
| 无数据 | 说明可以做什么，提供一个明确主操作 |
| 无权限/成员被移除 | 停止展示私有内容，提示重新选择可访问小组 |
| 网络失败 | 保留已填写内容，提供重试，不清空表单 |
| 重复提交 | 保持一个提交状态，演示稿也不重复新增卡片 |
| 图片失败 | 图片位置就地重试/移除，允许保存其他内容 |
| 并发编辑 | 提示刷新核对，不静默覆盖 |
| 无有效统计样本 | 显示“暂无数据”，不显示 0% |

手机以 390px 为主要设计宽度，并检查 320px；底部按钮避开安全区和软键盘，正文预留空间，不遮挡末尾内容。电脑以约 1200px 的内容宽度组织导航、列表和详情。

按钮触摸区域至少 44px；输入有持久标签，结果不只用颜色表达，键盘焦点可见。弹层有标题、关闭入口，关闭后焦点回到触发位置。

## 9. 本轮评审重点

1. 回顾页的日记感与暖白/陶土橙方向是否合适。
2. 游戏、玩家、结果集中在一页，是否足够容易完成。
3. 三种模式的结果选择是否容易理解，尤其是共同获胜和平局。
4. 小组页区分账号成员与昵称玩家，是否符合使用直觉。
5. 常用入口是否易找，统计是否抢占了回忆的位置。

数据库选型、真实登录、上传和 BGG 接入以 PRD、接口契约和正式业务实现为准。
