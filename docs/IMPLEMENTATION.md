依据：`PRD.md`、`FRONTEND_DESIGN.md`。

现有 Go 服务完成启动、统一响应、API 与 SPA 分流、前端资源嵌入；Vue 正式页面已接入真实业务接口。

正式页面沿用既有视觉与交互，使用业务 DTO、服务端数据和集中请求封装。仓库原有文件目前均为未跟踪状态，开发过程中保留，不自动提交。

## 已确认的选型（2026-09-18）

用户已确认 MySQL、SMTP、数据库 Cookie 会话，以及下列业务结果和数值规则；2026-09-19 将照片存储由本地私有目录调整为阿里云 OSS。

| 项目 | 最小方案建议 |
| --- | --- |
| 数据库 | MySQL，启动时按 Model 自动迁移；单实例运行；不使用外键，引用完整性由应用层校验，写事务内校验成员资格与版本 |
| 照片 | 阿里云深圳 OSS，Bucket `one-more-round`，前缀 `image/`；本地测试走公网、深圳服务器走内网。凭证只放私有 `config.json`，示例保持空值；数据库保存元数据与上传/就绪/删除状态，后端鉴权后读取，失败清理可重试 |
| 邮件 | SMTP，提供配置入口；联调可连接本地邮件收件箱，不输出验证码到应用日志 |
| 会话 | 随机 Cookie 凭据，数据库仅保存摘要，HttpOnly、生产 Secure、SameSite，写操作校验 CSRF |
| 组队结果 | 支持一队或多队获胜、全局平局、未记结果；结果和分数保存在队伍上 |
| 分数 | JSON 十进制字符串或 null；整数部分最多 12 位，小数最多 4 位；拒绝超精度，不静默舍入 |
| 邀请 | 2026-09-19 确认：试用邀请一次性注册；小组邀请允许注册并加入指定组，可多人使用；均为 7 天、可撤销，密钥只存摘要。邀请注册、成员关系与会话原子提交 |
| 玩家档案 | 创建小组时原子创建并关联组主档案；加入其他小组后选择新建或关联已有档案，两种申请均由组主确认 |
| 验证码 | 10 分钟有效、60 秒重发、最多尝试 5 次；一次性消费，并补充邮箱/IP 发送限流 |
| BGG | 授权配置后接入；未配置时明确告知不可用，手动添加始终可用 |

会话固定 30 天，CLI 发放/撤销一次性试用邀请；每邮箱每小时 10 次、每来源 IP 每小时 30 次发送请求。完整实现约束见 API.md。服务已部署到阿里云服务器并以 Docker 镜像运行（由 `server/*` 标签触发 ACR 发布），生产的真实 SMTP 与 OSS 凭证由部署环境注入。

持久化约定：14 张业务表使用独立 Go Model，通过锁定版本的 `gorm.io/gen` 生成 Query，由仓储调用。`make generate` 无需连接数据库；生成文件随源码维护。分层按业务边界组织：领域包 `internal/domain/{identity,group,game,diary,photo}` 各自声明仓储接口与领域服务；`internal/infra/mysql` 用 `RepositoryFactory` 汇总实现并以 `WithTransaction` 派生事务实例；应用层 `internal/app/services` 每个边界一个 `XxxApp`，经 `AppContext` 注入依赖。Model、Domain、DTO 三种模型保持分离，DTO ↔ Domain 转换集中在 `internal/app/mapper`，Model ↔ Domain 转换集中在 `internal/infra/mysql/mapper`，两个 Mapper 区域不跨边界依赖。对局 JSON 存储格式、Read Committed 隔离级别和小组行锁保持不变。

## 交付顺序与验证

### 1. 身份与小组

实现迁移、验证码登录、试用邀请、会话、小组创建/加入/切换、成员权限和昵称玩家。创建小组时同时建立组主玩家档案；加入其他小组后可新建档案或关联已有档案并等待组主确认。组合根注入数据库与 SMTP；应用层定义事务，领域层维护角色和关联约束。

验证：无邀请不能注册；验证码过期、重复消费、尝试限制；邮件失败明确反馈；非成员与已移除成员无权访问；重名玩家冲突；跨组资源拒绝访问。

### 2. 手动游戏与对局闭环

实现手动游戏、三种模式、创建/编辑/删除、回顾和详情。列表分页；日期使用北京时间日期语义。创建键按账号和小组限定，同键异内容冲突；编辑/删除原子校验版本。草稿按账号和小组隔离，保存失败保留，退出清除；再记一局创建新幂等键并清空结果与照片。

验证：共同获胜、平局、未记结果、合作与非法分队；负数、小数、空分数和零；500 个 Unicode 字符边界；并发创建只产生一条记录；版本冲突；事务失败不留下半条记录。浏览器完成一人记录整桌、编辑、删除及草稿恢复。

### 3. 首版管理与统计

实现邀请撤销、移除/退出、组主转让、玩家关联申请与确认、游戏和玩家详情，以及与列表筛选一致的统计。

验证：账号/档案并发关联唯一；组主转让一致性；撤销成员访问即时生效；各模式战绩隔离；平局计入分母，未记结果排除；无样本显示暂无数据；编辑删除后统计更新。

### 4. 照片与 BGG

照片独立上传，解码校验格式和资源上限，压缩、去除定位元数据，仅保存最长边 1600px 的一张私有 JPEG 展示图，所有展示入口统一读取；浏览器预压缩并顺序上传，服务端完整解码前限制宽高、上传全程单并发，清理未关联文件。BGG 接入前核实官方授权、接口和来源要求，实现超时、缓存、按小组去重、中文别名及组主确认合并。

验证：上传失败不丢表单；大小、格式、数量和跨组关联校验；成员移除后展示图与旧 URL 均不可访问；BGG 超时、限流、授权失败可降级，已有游戏不依赖在线服务。无真实授权时不标记外部检索完成。

### 5. 发布产物与试用

统一构建按安装锁定依赖、TypeScript 检查、Vite 构建、Go 测试/vet、二进制构建的顺序执行。将二进制复制到不含前端目录的临时目录，使用独立数据与配置启动，检查首页、深链接、静态资源、API 和缺失资源。

浏览器检查手机 320/390px 和电脑布局、键盘焦点、错误重试和核心流程。60 秒录入目标及两周真实小组试用需要真实用户参与，不能由编译通过或自动化操作代替。
